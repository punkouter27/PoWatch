AI & external services

Which outside helpers PoWatch uses, and what they are allowed to do

PoWatch has two kinds of AI. "Eyes and ears" run on your own computer and turn the camera and microphone into notes. A "writer" on the server may reword the notes into nicer sentences, but a spell-checker for numbers throws its work away if it makes up a single number.

On the server: the writer

One "writer" interface (IChatClient) can be backed by three providers. "Auto" tries the free local one first, then the cloud. Whichever answers, the same number check applies.

  1. ChooseGET/PUT /api/ai/models. The choice rides in an HttpOnly cookie for a year, and an unknown id is rejected with 400.
  2. Fence the factsCaptions, moment text and names go in as <facts>, with control characters and fence characters removed.
  3. Ask with a time limitEach model attempt gets its own timeout, and a failure moves on to the next model (AiFallback).
  4. Check the numbersKeepsToFacts rejects any number the facts do not contain, including spelled-out ones ("three", "a dozen").
  5. CacheReplies are cached by prompt, model and provider, so reopening a day costs nothing.

How long the server waits before giving up

Every outside call has a stopwatch. If a helper is too slow, PoWatch stops waiting and uses its fallback, so a page never hangs on an AI.

Cost & safety boundaries

Cost guards

  • Production defaults to Template, so it makes no paid AI calls until someone opts in.
  • "Auto" prefers free local Ollama, and the probe answer is trusted for 30 s.
  • Replies are cached by prompt, so the same facts never cost twice. The cache is in memory with a 200 MB cap and is lost on restart.
  • Ask may make at most four tool rounds, and its captions search looks back a bounded number of days.

Safety guards

  • Prompt injection: observed text is fenced data, and the system prompt says to ignore instructions inside it.
  • Hallucinated numbers: KeepsToFacts rejects any reply containing a number the facts lack.
  • Structured output: the model answers in a JSON schema, so there is no free-text parsing.
  • No secrets in labels: model labels show neither credentials nor endpoints.
  • Watch rules drafted by AI are checked against the 80 detector labels and real hours, then confirmed by the user.

Offline & fallback behaviour

If any helper is missing, PoWatch steps down a level rather than breaking.

What failsWhat the user sees
No network while recordingBatches wait in the IndexedDB outbox and are sent later. The app shell opens offline from the service worker.
No local OllamaCaptions come from in-browser Florence-2, and Settings shows which one ran.
No WebGPUThe models run on WASM, multi-threaded thanks to COOP/COEP.
Server AI slow, failing or inventing numbersThe next model is tried once, then the template recap or story stays.
No server AI at allRecaps and stories come from the template. Ask and rule drafting answer 503 with a reason.
QuestPDF native engine missingThe PDF link answers an explained 503.
No cameraA deterministic demo room (walker, dog, cat, cup, changing light) drives the same pipeline.
